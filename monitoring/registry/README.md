# Реестр нод

Источник данных для пунктов 1, 2, 15 и 22 ТЗ: домен, apex, регистратор, NS, УЦ,
сроки, роль, пара «вход — выход», провайдер, тариф, адреса.

Реестр не ведётся руками. Из одиннадцати полей девять выводятся из живых
источников, и только провайдер, тариф и учётная запись регистратора приходят от
человека.

## Три вида, один источник

| Вид | Где лежит | Что внутри |
| --- | --- | --- |
| публичный срез | `monitoring/registry/registry.yml` | роль, пара, метка семейства, УЦ, срок. Ни адресов, ни доменов |
| полная запись | `/etc/remnawave/registry.yml` на контроллере | всё выводимое плюс ручной слой; читается плейбуками как extra-vars |
| документ | хранилище заметок, `Реестр_нод.md` | полная картина плюс карта доступов, для рабочей машины |

Шов проходит там же, где у `monitoring/capacity/capacity.yml`, и по той же
причине: репозиторий публичный, поэтому всё, что сопоставляет имя машине или
называет её домен, живёт в `/etc/remnawave`.

`family` в публичном срезе — непрозрачная метка. Видно, сколько доменных
семейств у парка и как по ним разложены ноды; какие это домены — нет. Перечислить
домены в открытом репозитории значило бы своими руками собрать ту единую подпись,
которую пункт 1 ТЗ предлагает разводить.

## Как обновить

```
# на хосте панели: собрать выводимую часть
python3 collect_registry.py /root/registry-derived.json

# на контроллере: разложить в три вида
python3 render_registry.py registry-derived.json \
  --manual /etc/remnawave/registry-manual.yml \
  --private /etc/remnawave/registry.yml \
  --public  monitoring/registry/registry.yml \
  --doc     Реестр_нод.md
```

Сборщику нужен доступ к панели, рабочие резолверы и маршрут до нод на 443 —
поэтому он запускается на хосте панели, а не на рабочей машине.

## Откуда берётся каждое поле

| Поле | Источник |
| --- | --- |
| домен | панель, `realitySettings.serverNames` |
| apex, семейство | из домена |
| NS, регистратор | DNS-запрос NS по apex |
| УЦ, срок | TLS-хендшейк на 443 с нужным SNI |
| адрес | панель, `node.address`; расхождение с A-записью помечается отдельно |
| роль | наличие исходящего-моста; цель чужого моста делает ноду транзитом |
| пара «вход — выход» | мост называет цель своим SNI, тот резолвится в адрес ноды |
| провайдер, тариф, учётка регистратора | только человек |

## Что реестр показал сразу

Весь парк сидит на одном apex и одном УЦ, сертификаты истекают в пределах
двух недель друг от друга. Это единая подпись и общая точка отказа
одновременно — исходная точка для пункта 1.
