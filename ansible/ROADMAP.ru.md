# План доведения Ansible-установщика до продакшена

Обновлено 2026-08-28. Ветка `feature/ansible-automation`.

## Вводные

- Terraform не используется, VPS создаются руками, IP вносится в inventory вручную.
- Панель Remnawave — одна. Общий Xray-профиль — `Default August`, в нём routing.
- Все домены на reg.ru.
- Основной протокол — VLESS + TCP/raw + Reality + Vision. Критично: сертификат на домен
  и правдоподобный сайт-заглушка, за которым идёт маскировка.
- SNI-mirror и front-gate в прод-схему не входят → бэклог.
- Запуск с устройства сейчас, Semaphore UI следующим этапом. Абсолютных путей в проекте
  нет, поэтому переезд — это только конфигурация.
- Модель безопасности ноды: nftables со своей изолированной таблицей и таймером откатa,
  `management_cidrs`, fail2ban и минимум открытых портов. Ничего поверх этого не ставим.

## Сделано

**UI можно опубликовать, не выставляя саму панель.** Semaphore по-прежнему слушает
только loopback; наружу смотрит nginx, чья работа — TLS, список допущенных адресов
и проксирование на `127.0.0.1:3000`. Роль после применения проверяет через `ss`, что
443 публичный, а порт панели — нет. Сертификат берётся по HTTP-01: первый проход
поднимает HTTP-сайт, отвечающий на challenge, и только после выпуска пишется
TLS-сайт, поэтому опубликовать что-либо без сертификата нельзя. Preflight не даст
вызвать certbot, если имя не резолвится на этот хост — лимит Let's Encrypt пять
неудач в час на hostname расходовать не на что.

Три вещи, которые здесь важнее самого TLS. Пустой `controller_proxy_allowed_cidrs`
требует явного `controller_proxy_ack_public: true` — за этим логином машина,
которая ставит все ноды. Basic auth перед логином Semaphore принимает только хеши,
а значение, похожее на пароль, отклоняется в preflight (nginx принял бы его молча и
не аутентифицировал никого). И маршруты, которые Semaphore 2.18.29 отдаёт **без
аутентификации** — `/api/integrations/{alias}`, `/api/terraform/{alias}`,
`/api/internal/runners` — на публичном инстансе закрыты 404: угаданный alias
запускал бы задачу на парке.

WebSocket с живым выводом задачи проксируется явно (`Upgrade`/`Connection` плюс
`map` в http-контексте, read timeout час) — без этого UI грузится, а запущенная
задача молча не показывается.

**Регистрация.** В 2.18.29 маршрута самостоятельной регистрации нет вообще,
выключать нечего: аккаунты появляются только потому, что их создал администратор.
Роль дополнительно держит `non_admin_can_create_project: false`, а второй оператор
создаётся `semaphore_bootstrap.py --add-user` — не админом и с ролью `task_runner`,
то есть может нажимать три кнопки и читать логи, но не переписать шаблон.

**Реальные значения доходят и до UI, и до CLI.** Semaphore клонирует репозиторий на
каждый job, поэтому git-ignored файл внутри чекаута до запуска из UI не доезжает
никогда, а репозиторий публичный, поэтому закоммитить значения нельзя. Оба пути
теперь читают два файла на контроллере — `/etc/remnawave/fleet.yml` и
зашифрованный `/etc/remnawave/secrets.yml` — как extra-vars: обёртка добавляет их
сама, шаблоны Semaphore называют их в своих аргументах. Зашифрованный extra-vars
файл ещё и оставляет секрет вне командной строки, в отличие от `-e name=value`,
который Semaphore пишет в argv. Variable Group не содержит значений вообще, кроме
пути к паролю vault.

**Документационные значения не могут доехать до ноды.** Preflight отказывается
работать, если видит `panel.example.com`, зону `example.com` или
`ops@example.com`: прогон, потерявший файл значений, останавливается вместо
публикации ноды против несуществующей панели.

**Парковую идентичность нельзя подсунуть глобально.** Extra-vars перекрывают всё,
включая host_vars, поэтому один `node_id` или `ansible_host` в Variable Group даёт
всему парку одну идентичность, и каждый прогон перезаписывает объекты предыдущей
ноды. Preflight пересчитывает идентичность из имени хоста в inventory и падает при
расхождении; осознанное исключение — `node_identity_override_ack: true` в блоке
конкретного хоста.

**Одна точка запуска.** В репозитории остался единственный `ansible.cfg` — в корне.
`ansible/ansible.cfg` удалён, обёртки `provision-node` и `setup-controller` переехали
в корень, `collections_path` указывает внутрь чекаута, поэтому коллекции версионируются
вместе с проектом и видны сервисному пользователю с `ProtectHome=true`. Ни одна
документированная команда больше не требует `ANSIBLE_CONFIG`.

**Парковые переменные не зависят от источника inventory.** `group_vars` переехали к
плейбуку: `playbooks/group_vars/all/{panel,countries}.yml` и
`playbooks/group_vars/remnawave_nodes/{identity,fleet}.yml`. Это единственное
расположение, которое грузится при внешнем inventory Semaphore, и оно приоритетнее
инвентарного — поэтому реальные значения теперь лежат в git-ignored
два файла на контроллере (`/etc/remnawave/fleet.yml` и зашифрованный `secrets.yml`),
которые грузятся как extra-vars, а не рядом с inventory, где их молча перекрыл бы
документационный пример. Две дословные копии парковых файлов под
двумя inventory и тест, который следил за их синхронностью, больше не нужны.
`tests/test_external_inventory.sh` собирает инвентарь из одной строки и требует, чтобы
нода развернулась целиком; `playbooks/show_node_identity.yml` показывает результат
оператору без сервера и без секретов.

**Одна строка на ноду.** `node_host_remark` выводится из таблицы стран
`group_vars/all/countries.yml`, поэтому в inventory остаётся только `ansible_host`.
Неизвестный код страны останавливает прогон с путём к файлу и готовой строкой для
добавления, а не публикует Host с пустой подписью.

**root/password сохранён как резервный вход.** Дефолт роли остался безопасным
(`false`) для всех остальных, а парковая конфигурация включает
`node_ssh_allow_root_password: true` явно. Drop-in переименован в
`00-remnawave.conf`: sshd берёт первое найденное значение, и вендорский или
cloud-init файл с более ранней сортировкой иначе молча переопределил бы политику.
После записи выполняется `sshd -t`, затем `sshd -T`, и итог сверяется с
запрошенной политикой.

**Общий профиль защищён от конкурентной записи.** Слияние инбаунда — это
read-modify-write, поэтому профиль перечитывается непосредственно перед PATCH и
сверяется по SHA-256 с тем, что прогон читал в начале: второй прогон или правка
руками в панели приводят к отказу без записи, а не к потере чужого изменения.
После записи проверяется, что ни один инбаунд, который был в профиле до прогона,
не исчез. `inbound_prune_tags` может называть только теги из пространства имён
этой ноды. Adoption чужого профиля требует явного `profile_uuid`, а не совпадения
тега. Пустой список профилей от панели считается сбоем, а не пустой панелью.
Инбаунд с протоколом, который панель не вырезает по нодам, запрещён без явного
allowlist — иначе он уехал бы на весь парк целиком. Всё это покрыто
`tests/test_shared_profile_concurrency.sh` на моке, который меняет профиль между
чтением и записью.

**Preflight разделён, DNS между половинами.** Панельные проверки — отдельный play
без подключения к ноде, поэтому они проходят до изменения зоны у регистратора и
работают даже до создания VPS; DNS реконсилится вторым play; проверки, которым
нужен сам сервер, идут третьим. Шаблон Semaphore `Preflight` теперь действительно
ничего не меняет: состояние DNS он сообщает, а не создаёт, и падает только если
`dns_provider: none` и запись уже неверна — тогда её не исправит ничто.

**Область прогона ограничена.** `install_node.yml` отказывается работать, если
`--limit` разрешился больше чем в один хост, пока не задан `node_allow_bulk=true`;
оба изменяющих play идут `serial: 1`.

**Список управляющих адресов.** Исправлена расстановка скобок: `| unique` связывается
крепче, чем `+`, поэтому адрес, найденный из живой сессии и одновременно указанный в
`management_cidrs_extra`, попадал в правило дважды. Поведение вынесено в отдельный
файл задач и покрыто `tests/management_cidrs.yml`, включая главный случай: явный
список, который отрезал бы Controller, отклоняется, а не применяется.

**Пароль bootstrap не утекает в логи.** Play, который заходит с паролем, целиком
подавляет вывод и отказывается работать при `-vv` и выше, потому что Semaphore
передаёт секреты через `--extra-vars` в командной строке.

**Сертификаты без простоя.** Certbot переведён с `--standalone` на `--webroot`: HTTP-01
отвечает из каталога, который nginx уже отдаёт на `/.well-known/acme-challenge/`.
Standalone остаётся только для самой первой установки, когда nginx ещё не запущен и
прерывать нечего. Таймер обновления больше не останавливает nginx и перезагружает его
только когда сертификат реально изменился.

**ACME staging/production.** `certificate_acme_environment` выбирает CA. Переключение
между окружениями определяется по issuer сертификата и вызывает чистый перевыпуск, а
установка падает, если поставленный сертификат не соответствует запрошенному окружению —
staging-сертификат не может незаметно попасть в прод.

**Привязка Hosts к `Default August`.** Панельная роль больше не создаёт профиль на каждую
ноду. Она читает общий профиль, вливает в него инбаунд этой ноды по тегу и записывает
обратно: чужие инбаунды сохраняют свои UUID и свои Reality-ключи, `routing`, `dns`,
`outbounds` и `policy` переносятся без изменений. Reality-ключ ноды ищется по её
собственному тегу, поэтому нода не может подобрать ключ соседа. Node активирует только
свой инбаунд, каждый Host публикуется на UUID общего профиля и UUID своего инбаунда, и
после реконсиляции Hosts перечитываются с проверкой этой привязки. Отсутствующий общий
профиль не создаётся молча — прогон останавливается с объяснением.

**Идемпотентность.** Второй прогон панельной роли давал `changed=2` и до этого не
проверялся ни разу. Причины: тестовый плейбук перезаписывал `.env`, который роль пишет
сама; `activeInbounds` и `nodes` панель возвращает объектами, а сравнивались они со
строками UUID; `port` уходил в payload строкой. Исправлено, второй прогон даёт
`changed=0` и в обычном, и в bridge-сценарии.

**Bootstrap.** Роль `node_bootstrap` и `playbooks/bootstrap.yml`: доверие host key,
python3 через `raw`, создание `deployer` с ключом контроллера и sudo без пароля, затем
отдельный play, который заходит уже этим аккаунтом и проверяет, что escalation работает.
sshd не трогает — им владеет `node_base`.

**Минимум переменных на ноду.** На новую ноду в inventory нужны три факта:
`ansible_host`, `node_id`, и домен (если он не выводится из зоны). `node_name`,
`node_country`, `node_public_ip`, `selfsteal_domain`, тег инбаунда, `host_specs` и
`selfsteal_virtual_hosts` выводятся в `group_vars`. Отдельный файл-реестр `nodes.yml`
больше не нужен: `hosts.yml` и есть реестр.

**Реальные адреса убраны из git.** `inventories/test/`, `inventories/local/`,
`inventories/production/hosts.yml`, `playbooks/group_vars/all/vault.yml` и
`playbooks/group_vars/all/vault.yml` в `.gitignore`,
в git лежат `*.yml.example`. Пример не может называться `*.example.yml`: Ansible грузит
любой `.yml` из `group_vars`, и такой файл определял бы реальные переменные — на это есть
регрессионный тест.

**Уникальная заглушка на каждой ноде.** Сайт-заглушка генерируется из стабильного seed
ноды: тот же узел получает байт-в-байт тот же сайт всегда, разные узлы — разный бренд,
тексты, набор и порядок секций, вёрстку, палитру, шрифты, имена CSS-классов, имена
файлов ассетов, favicon, набор security-заголовков и размер ответа. Значения берутся из
SHA-256 от `seed | метка поля`, а не из одного потока `random`: поток зависит от версии
интерпретатора, а последовательная выборка означала бы, что добавление одного нового поля
сдвигает все следующие и перегенерирует сайты всего парка при правке шаблона. Ассеты
пишутся под именами из того же seed, файлы от предыдущего seed удаляются из document root.
`node_verify` требует, чтобы публичная страница содержала бренд, классы и имена ассетов
именно этой ноды.

**DNS-автоматизация.** Роль `dns` с провайдер-абстракцией (`dns_provider: regru|none`)
владеет ровно одной записью — A-записью selfsteal — и не трогает в зоне больше ничего.
Читает зону, сравнивает, создаёт при отсутствии, перенаправляет при неверном IP, при
корректном состоянии не меняет ничего. Вторая A-запись с тем же именем не угадывается, а
сообщается; удалить лишние можно только явным `dns_prune_extra_records=true`. После
изменения прогон ждёт, пока публичные резолверы начнут отдавать нужный адрес — ACME и
preflight самой ноды оба разрешают это имя. Логика решения провайдер-независима и покрыта
юнит-тестами плюс мок-регистратором.

**Один entry point.** `playbooks/provision_node.yml` выполняет bootstrap и установку
подряд и безопасен для повторного запуска: `bootstrap.yml` сам определяет, нужно ли ещё
создавать управляемый аккаунт (пробный коннект под `deployer`, `ignore_unreachable`).
`bootstrap.yml` и `install_node.yml` остаются отдельно запускаемыми для отладки.

**Тесты.** Общий профиль в mock-панели засеян чужим инбаундом и routing-правилами, тест
проверяет слияние, сохранность чужого ключа, привязку Host и Node и `changed=0` на втором
прогоне. Добавлены юнит-тесты новых фильтров и рендер всех трёх транспортов (raw, xhttp,
grpc-tls). `yamllint`, `ansible-lint` (профиль production), `validate_structure`,
`render_templates`, три панельных сценария, мок-регистратор DNS и валидация nginx-конфига
— зелёные. `nginx -t` в пиннутом образе гоняется в CI (в среде разработки нет docker), а
локально конфиг проверяется парсером crossplane.

## Осталось

### 1. RKN/DPI hardening — доделать

Есть: sysctl (`tcp_rfc1337`, syncookies, redirects, `rp_filter`, BBR+fq), отключение
dccp/sctp/rds/tipc, fail2ban, sshd-политика с проверкой через `sshd -T`.

Нет: нормализация TTL/hoplimit=128 в postrouting mangle (в bash — таблица `inet rknnode`),
подавление SSH-баннера (`DebianBanner no`, `Banner none`), `icmp_echo_ignore_broadcasts`,
`icmp_ignore_bogus_error_responses`, `accept_source_route=0`.

Риск: TTL=128 ставится после Docker NAT — проверить на Molecule и на живой ноде, что не
ломается трафик контейнеров и правило не дублируется при повторном прогоне.

### 2. Torrent Blocker

В bash `setup_torrent_blocker` копирует текущий `pluginConfig` перед переключением и
мержит `.torrentBlocker`. В Ansible generic-CRUD node-plugin есть, но PATCH перезаписывает
`pluginConfig` целиком (теряются `webhookUrl`, `rulePlacement`) и нет копирования текущего
профиля. Делаем структуру `torrent_blocker` с merge-семантикой и тестом в mock-панели.

### 3. XHTTP / gRPC-TLS — обвязка

Шаблоны уже поддерживают `raw`, `xhttp` и `grpc-tls`, рендер всех трёх покрыт тестом.
Осталось: валидация портов (в bash `xhttp_port_reserved` запрещает коллизии с
80/443/NODE_PORT/selfsteal/SSH/45876), ветки в `node_verify`, примеры в inventory,
описание режима `both`.

### 4. Sysctl и лимиты из `optimize`

Сверить с текущим `node_sysctl` и добавить недостающее: `somaxconn`,
`netdev_max_backlog`, `nf_conntrack_max`, `fs.file-max`, `nofile` для docker.

### 5. Операционные плейбуки

| Плейбук | Назначение |
|---|---|
| `update_node.yml` | обновление образа RemnaNode/Xray/geodata, `serial: 1`, проверка после каждой ноды |
| `rotate_keys.yml` | явная и раздельная ротация Reality-ключей, `SECRET_KEY`, bridge-секрета |
| `replace_node.yml` | замена при блокировке: новая нода → установка → перенос `host_specs` → старая в decommission |
| `decommission.yml` | снять Hosts, удалить Node из панели, погасить сервисы |
| `healthcheck.yml` | только `node_verify`, регулярный прогон по парку |
| `uninstall.yml` | паритет с `cmd_uninstall` из bash-CLI |

`replace_node.yml` уже опирается на готовый механизм: `inbound_prune_tags` убирает из
общего профиля инбаунд, который нода больше не обслуживает.

### 6. august-routing-updater — отдельный плейбук

Updater общается только с API панели (Response Rules, заголовок `routing` по User-Agent),
тянет JSONSUB-профили RoscomVPN для HAPP и INCY, крутится на хосте subscription page. К
нодам отношения не имеет и в `install_node.yml` не попадает — иначе N нод станут N
ежедневными писателями в один ресурс панели. Делаем роль `routing_updater` +
`playbooks/routing_updater.yml` + группу `subscription_page`, с сохранением текущего
hardening unit'а и токеном из vault.

### 7. Тест на живой ноде (следующий milestone)

Все статические и мок-проверки зелёные, но ни одна строка ещё не проверялась на реальной
системе, поэтому конвейер не production-ready. Новых возможностей до живого теста не
добавляем. Проверяем полный путь на чистом VPS: bootstrap → firewall → Docker → DNS →
ACME → nginx и заглушка → Remnawave API → `Default August` → Node → Host → Squad → Xray →
online → verification → повторный запуск с `changed=0`. ACME на первом прогоне — staging,
затем переключение на production (роль должна сама перевыпустить сертификат).

## Бэклог

- **Front-gate (`--front-ip`)** — таблица `inet mirror_gate`, 443 только с адресов фронта.
- **Роль `sni_mirror`** (`install-mirror.sh`) — nginx stream + `ssl_preread`, свой SNI →
  backend:443, неизвестный SNI → reset, open relay только по явному флагу. Обе связки
  (`front_ips` на бэкенде и `backend_ip`/`sni` на фронте) обязаны выводиться из одной
  записи inventory, иначе при замене фронта нода станет недоступной.
- **`node-accelerator` как внешний вызов** — не портируем. Своя таблица
  `remnawave_filter` с `nft -c` и таймером откатa функционально заменяет `na_filter` и
  safety-timer; запуск чужого bash-инсталлятора из Ansible запрещён ТЗ и создаёт двух
  владельцев firewall. На нодах, миграированных с bash, `na_filter` нужно снять, иначе
  будет два набора правил.
